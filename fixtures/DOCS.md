
# Bozor — документация проекта

Маркетплейс, объединяющий множество отдельных физических магазинов. Бизнес-проект (не учебный).

Репозиторий: https://github.com/yunusrf275-commits/bozor.git

---

## Стек

- Python 3.12
- Django 6.0.7
- PostgreSQL (база `bozor_bd`)
- Bootstrap 5 (подключён локально, без CDN)
- python-decouple (переменные окружения через `.env`)
- Pillow (работа с изображениями)
- psycopg (драйвер PostgreSQL)

Полный список версий — в `requirements.txt`, обновлять командой:
```bash
pip freeze > requirements.txt
```

## Структура настроек

```
config/settings/
    base.py        — общие настройки
    local.py        — локальная разработка (from .base import *)
    production.py   — прод (пока не настроен)
```

Секреты (`SECRET_KEY`, данные БД) — в `.env` (не в git), читаются через `python-decouple`.

`manage.py` настроен на `config.settings.local` по умолчанию — команды `runserver`/`migrate` работают без флага `--settings`.

## Роли пользователей (задумано)

1. **Главный админ** — управляет регионами, категориями, магазинами; блокирует/разблокирует магазины. Заходит только через стандартную Django admin-панель (`/admin/`), отдельной роли в модели `User` не имеет — определяется через `is_staff`/`is_superuser`.
2. **Владелец магазина** — управляет своим магазином (товары, статистика), создаёт своих админов с разными уровнями доступа (список уровней, не произвольные права), принимает заявки и продаёт через QR-код. Роль `shop_owner`. Регистрируется не сам — его создаёт главный админ после проверки документов, выдаёт логин/пароль.
3. **Покупатель** — может покупать без регистрации (указывает телефон продавцу перед отправкой корзины). Регистрация нужна для комментариев, истории покупок, избранных магазинов. Роль `customer`.

Вход у покупателя и продавца — на разных страницах, но одна модель `User` с полем `role`. Обязательная проверка роли на сервере при входе (не полагаемся на "скрытость" URL).

## Приложение `locations`

Модель `Location` — самоссылающаяся (одна модель на все уровни, без хардкода названий):

```python
class Location(models.Model):
    name = CharField
    parent = FK('self', null=True, blank=True, related_name='children')
    level = PositiveSmallIntegerField()  # 1=viloyat, 2=tuman, 3=село (опционально)
    slug = SlugField(unique=True, auto-generate из name)
```

Защита от неправильной вложенности — метод `clean()`: level 1 не может иметь родителя; level > 1 обязан иметь родителя уровня `level - 1` (проверка "бабушка → мама → внучка").

Магазин привязывается либо к туману (level 2, если это районный центр без своего села), либо к селу (level 3, если известно конкретное село) — оба варианта равнозначны для модели `Shop`.

**Management-команды:**
- `load_locations` — грузит `fixtures/viloyat_tuman.json` (14 областей + 199 туманов Узбекистана)
- `add_test_villages` — тестовые данные: по одному селу на каждый туман (имя вида `<туман>1`)

**Admin:** поиск по названию (`search_fields`), фильтр по уровню, `autocomplete_fields` — специально вместо каскадных select'ов (признано избыточным для редких ручных добавлений главным админом).

**AJAX-эндпоинт:** `GET /locations/get-children/?parent_id=<id>` → JSON со списком дочерних locations. Используется в модалке выбора региона в навбаре.

## Приложение `shops`

Модель `Shop`:

```python
class Shop(models.Model):
    name = CharField
    slug = SlugField(unique=True, auto-generate)
    location = FK(Location, PROTECT)
    owner = FK(settings.AUTH_USER_MODEL, PROTECT, null=True, blank=True)
    logo = ImageField(upload_to='shops/logos/%Y/%m/', blank=True)
    is_active = BooleanField(default=True)  # единственный переключатель вкл/выкл
```

Решения:
- **Нет отдельного поля `category`** — магазин продаёт разное, категории определяются через категории его товаров (когда появится `products`), не хардкодятся на самом магазине.
- **Нет поля `status`** (проверка документов) — убрано как избыточное: проверка документов происходит офлайн до создания магазина в системе, поэтому в БД магазин уже создаётся "одобренным". Включение/выключение — только через `is_active`.
- `owner` — `null=True, blank=True` пока не подключена реальная привязка продавца к своему магазину при создании (следующий шаг).

**Management-команда:** `create_test_shops` — по одному тестовому магазину на каждую locations уровня 2 и 3 (название `Do'kon <название локации>`).

## Приложение `accounts`

Кастомная модель пользователя (обязательно настраивается в самом начале проекта, до первых миграций — иначе потребуется полный сброс БД):

```python
class User(AbstractUser):
    role = CharField(choices=[('customer', 'Покупатель'), ('shop_owner', 'Владелец магазина')], default='customer')
    phone = CharField(blank=True)
```

`AUTH_USER_MODEL = 'accounts.User'` в `config/settings/base.py`.

**Вход продавца:** `/accounts/seller/login/` — проверяет `role == 'shop_owner' and not is_staff`.
**Вход/регистрация покупателя:** `/accounts/login/`, `/accounts/register/` — проверяет `role == 'customer' and not is_staff`.
**Выход:** `/accounts/logout/`.

Пароли — только через `User.objects.create_user()` (хэширует автоматически). Одинаковый текст ошибки для "неверный пароль" и "неверная роль", чтобы не раскрывать существование аккаунта с другой ролью.

Суперпользователь (`is_staff`) исключён из обоих пользовательских входов — заходит только через `/admin/`.

## Приложение `pages`

- `home` (`/`) — главная страница.
- Список магазинов: фильтр по `is_active=True`, опционально по выбранному региону.
- **Рандом + пагинация по 20** — список id перемешивается один раз и сохраняется в сессию (ключ `shops_order_<location_id>`), чтобы при подгрузке следующих страниц магазины не терялись/не дублировались. При смене фильтра — новый ключ сессии, новый рандом.
- **Бесконечная прокрутка** — AJAX через `?ajax=1&page=N&location=X`, IntersectionObserver в `static/js/main.js` подгружает `pages/_shop_cards.html` (партиал с карточками) при достижении низа страницы.
- Функция `get_descendant_ids(location)` — собирает id локации + все её дочерние + внучатые, чтобы фильтр по региону учитывал магазины, привязанные на любом вложенном уровне.

**Навбар** (`templates/includes/navbar.html`):
- Кнопка "Регион" → модалка с пошаговым выбором (все области → клик → её районы, с полем поиска на обоих экранах). Список областей рендерится через context processor `locations.context_processors.regions`.
- Кнопка "Войти"/имя пользователя + "Выйти" (для покупателя).

**Футер** — планируется страница "О нас" и другие информационные страницы внутри `pages` (ещё не наполнены).
